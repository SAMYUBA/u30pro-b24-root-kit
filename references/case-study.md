# 单机案例复盘

## 范围与结果

本案例来自一台 U30 Pro / MU5358、U30ProHW1.0、U30ProV1.0.0B24，主机为 Apple Silicon Mac。设备标识、账户、密钥、个人目录和原始日志均未纳入公开项目。

最终证据：Magisk 30.7；Mac 通过 ADB 连续 7 次取得 `uid=0(root)`；本次重启后约 4–5 分钟时 ADB 仍稳定；USB 授权校验开启、TCP ADB 关闭。设备使用者确认首页与 Wi-Fi 上网正常。

这是一次成功实机案例。公开工具是在该过程中使用的单机方法上进行参数化、审计和整理，不能宣称公开版所有分支都经过真实设备测试，也没有跨设备成功率数据。

## 过程

| 阶段 | 做了什么 | 得到了什么证据 |
| --- | --- | --- |
| 原方案调研 | 阅读原作者 Skill、发布材料、成功与失败记录，核对主机差异 | B24 特定路线可作为起点；Windows 成功不直接保证 Mac USB 行为 |
| 原厂基线 | 检查版本、硬件、USB、网页与 Wi-Fi | 设备正常；Mac 常态接口为 NCM + MTP，没有可用 ADB |
| 备份审计 | 读取选定分区、重复核对关键静态分区；检查启动链和 AVB | 静态关键数据一致；NV 长会话不一致需单列，冷读复核不能替代恢复演练 |
| 主机适配 | 使用本机 ADB 公钥准备候选；保留镜像结构与既有有效数据 | 候选差异可审计；没有分发或依赖他人的授权密钥 |
| TrustOS 阶段 | 仅写计划中的 TrustOS B，读回核验后重启 | 首页和 Wi-Fi 继续正常 |
| 首次 init_boot | 写入含 Magisk 的本机候选，完整读回 | 镜像写入成功，但没有稳定 ADB；不能仅凭此判定 Root 失败 |
| 调整 ADB 启动顺序 | 将 USB 初始化提前 | 仍未获得稳定主机连接，说明顺序调整不足以解决问题 |
| 受限启动观察 | 短时观察器经已有 SMB 共享输出白名单日志 | 内部 root 与 Magisk 已存在；USB 从 `ncm,mtp,adb` 回退为 `ncm,mtp`，adbd 停止 |
| 框架设置实验 | 防误操作校验后把全局 `adb_enabled` 从 0 改为 1，立即读回 | 设置写入成功；首次观察仍出现 USB 回退，后续设置值当时未知 |
| 原厂 USB 设置与重启 | 用户将 Auto 改为 RNDIS 并重启，主机只读等待连接 | 得到稳定 ADB Root；最终实际接口仍为 NCM + MTP + ADB |
| 验收 | 多次 root、版本及安全状态检查，用户检查网络 | 本次 Root 目标完成；长周期可靠性与完整恢复未实测 |

所有实际刷写都有固定分区、写前检查、写后读回和重启条件约束。调试时没有通过擦除 userdata、改写 NV 或重分区来“碰运气”。

## 可以得出的结论

- 原始故障的核心现象是 USB ADB 生命周期与主机可达性；内部 Root 已经建立。
- 全局 ADB 设置、原厂 USB 协议偏好和启动时序都值得检查。
- 成功配置来自累积调整，不能把最后一次 RNDIS 操作当成唯一必要或充分条件。
- 日志中曾出现 SELinux Permissive；USB 认证和禁用 TCP ADB 不能等价于恢复原厂安全边界。
