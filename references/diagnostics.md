# 有限启动观察器

用途：设备内部 Root 已启动、但主机抓不到稳定 ADB 时，观察开机初期的 USB 状态变化。**已经稳定获得 Root 的设备不建议为了诊断再次刷写。** 本项目整理期间没有为生成公开代码而再次访问或修改实机。

## 可选构建与取回

候选 builder 的 `--observer` 选项把观察分支拼接进启动 helper，并生成仅供本地使用的 `u30-diag-enable.txt`。它不是常驻服务，不会自行开启 Samba 或远程 ADB。命令完整参数以 README 为准。

1. 在本地按需要构建诊断候选，完成与普通候选相同的镜像审计和备份门禁。
2. 通过设备原厂界面启用文件共享，由用户自行登录；不要将凭据写入脚本。
3. 将 builder 生成的 marker 原样复制到共享根目录。本案例原厂共享根目录对应设备 DCIM。
4. 观察器启动后只接受 marker 完整字节等于随机 token 加一个 LF。不要编辑、追加空行或提交这个文件。
5. 从同一共享目录读取 `u30-diag-runtime.txt`，仅保留需要的本地证据。重启后共享可能要重新连接；USB 协议变化导致 USB 网络不可用时，可用设备自身 Wi-Fi 访问共享。

观察分支由 helper 参数 `--observe` 启用；没有该参数时继续执行后面的正常 Root helper。builder 的 init 配置负责在相应启动阶段调用它。不要把 shell 模板当成可直接在 Mac 上运行的诊断命令。

## 数据范围与时限

每次启动最多尝试 24 个 snapshot，间隔 5 秒。约两分钟只是名义窗口；命令耗时、Android 服务阻塞及调度可能延长实际运行时间，它不是强制墙钟超时。

记录内容为白名单 USB/启动属性、当前 `adb_enabled`、运行身份、SELinux 状态、Magisk/adbd PID 和本次 boot ID。不会读取完整属性表、完整 settings 库、个人文件、凭据或其他日志。framework 尚未就绪时，相关字段记为 `unavailable`，观察继续。

只向 `/mnt/sdcard/DCIM` 或 `/data/media/0/DCIM` 写入。每次写入前检查 marker、输出文件类型及符号链接；首选路径不可写时尝试后备路径。缺少 marker、marker 不匹配或目标不安全时不写。文件共享位于第三方可写目录时，不应把这些检查视为对恶意并发替换路径的完备防护。

## 阅读方式

- 同一文件跨启动追加；按 boot ID 和 snapshot 重新从 0 开始的边界区分，PID 不足以单独标识启动。
- snapshot begin/end 不成对时，可能正在读取尚未写完的记录；不要用半条记录推导状态顺序。
- `uid=0(root)` 说明观察进程权限；Magisk PID 说明进程存在；它们都不能证明主机 ADB 会话稳定。
- 将 `sys.usb.config`、`sys.usb.state`、`sys.usb.ffs.ready`、`init.svc.adbd`、`adb_enabled` 放在同一时间序列中比较。属性变化能定位阶段，不能单独识别回写者。
- 没有日志可能是共享未挂载、marker 未到位、文件不可写或观察窗口已过，不能直接判定 Root 失败。

诊断完成后移除共享中的 marker 和报告副本，停止不需要的主机监听。移除 marker 后后续启动不会再写诊断报告；保留的镜像仍包含有限观察代码。若决定换回无观察器候选，应按完整刷写门禁执行，不为清理临时文件而贸然重刷。
