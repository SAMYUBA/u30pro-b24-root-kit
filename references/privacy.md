# 公开项目的隐私边界

公开内容仅包括自行编写的通用代码、公开来源链接、必要的公共产品信息和经过脱敏的经验总结。诊断、备份和候选镜像留在使用者本地，不通过 Issue、PR、Release 或 CI artifact 自动上传。

## 不得提交

- 真实序列号、IMEI、IMSI、ICCID、MAC 地址、设备唯一标识和个人账户。
- 姓名、邮箱、家庭网络信息、个人目录路径、主机名、共享登录凭据。
- ADB 私钥；也不提交个人 ADB 公钥，因为它可关联或授权特定主机。
- Wi-Fi 密码、token、SSH 密钥、证书私钥、随机诊断标记。
- 原始设备分区、NV、userdata、metadata、配置导出和未审查的终端日志。
- 注入本机公钥或标识的候选镜像、生成配置、执行结果和 USB 绑定资料。

公钥不是私钥，但公开项目没有收集个人公钥的必要。摘要也不是匿名化：设备专属镜像或文件的哈希可能成为稳定关联标识，不发布这类摘要。

## 应当使用

- 环境变量、本地参数文件或运行时输入；示例只用明确的占位符。
- 合成测试 fixture 和人工构造的协议响应，不裁剪真实备份充当 fixture。
- 白名单诊断字段：软件版本、脱敏后的 USB 接口类型、服务状态、root 是否成功、实验顺序。
- 公开上游发布文件的版本与校验值；明确区分上游公共文件与本机生成文件。

## 发布前审查

1. 从新的干净目录组装可公开项目，不从私有工作目录整树复制。
2. 检查所有待提交文本、二进制和隐藏文件，确认不存在第三方未许可实现、固件、真实日志及设备标识。
3. 执行自动扫描，再人工查看暂存 diff；自动扫描只能补充人工审查，不能证明没有 PII。
4. 检查 Git 历史与 Release 附件。删除当前文件不会删除历史中的敏感信息。
5. 检查链接、图片元数据、截图、CI 输出与失败报告，不只检查源码。

若已误公开密钥或 token，应立即撤销或轮换，再处理历史与缓存；不能仅依赖删除文件。提交问题报告时使用合成标识，并以最少必要字段描述问题。
