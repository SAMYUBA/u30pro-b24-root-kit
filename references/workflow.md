# 工作流：先核对，再写入，最后验收

适用范围是 ZTE U30 Pro / MU5358、硬件 U30ProHW1.0、固件 U30ProV1.0.0B24 的一次 macOS 实机经验。型号相同并不足以证明分区、启动链和固件相同。本项目的泛化工具经过离线检查，不代表已经在第二台设备上验证。

原方案与设备资料以[原作者项目](https://github.com/qwXZhong/u30pro-b24-root-skill)为起点。具体 CLI、依赖下载入口以本项目 README 为准；下面说明每个阶段必须获得的证据，不能替代执行工具的参数校验。

## 0. 建立边界

- 仅操作本人所有或获得明确授权的设备，确认用户接受失去保修、断网、数据损坏及无法恢复的可能性。
- 明确工作目录、备份目录和设备身份；所有设备数据置于公开 Git 工作树之外。
- 保留可靠电源、数据线、正常 Wi-Fi 管理路径。改变 USB 网络协议可能让 Mac 的 USB 网络断开。
- 不自动升级固件，不修改其他网络设备，不上传诊断原件。

## 1. 只读预检

输入：已正常启动的目标设备、Mac、本地官方 Platform-Tools、原作者公开资料。

核对型号、硬件、完整固件版本、当前启动槽位、USB 描述符、已有 ADB 状态和系统首页。记录 Wi-Fi 上网基线。USB PID 不能单独代表 ADB 可用；必须检查接口 class/subclass/protocol 和 ADB 实际响应。

输出：只在本地保存的设备绑定资料与兼容性结论。信息不符或无法确认时停止写入，不能把型号相近当作兼容。

## 2. 获取和审计依赖

从原作者和各上游官方入口获取文件，记录固定版本、来源、SHA-256、大小与许可证。公开可下载不等于允许重新分发；本仓库不随附作者固件包、第三方二进制或设备备份。

审计候选镜像的 boot header、ramdisk、CPIO 路径、压缩格式、AVB footer/descriptor 和 Magisk 版本。根据本机 ADB **公钥**生成本机候选，不使用作者的授权公钥，也不读取或分发私钥。候选镜像依旧不应上传公开仓库。

保留 OEM vbmeta 签名数据并不使修改后的镜像获得 OEM 签名。需要分别说明签名 blob 验证结果与 descriptor 对修改后 body 的匹配结果。

## 3. 下载模式、备份与恢复准备

按已核对的原作者步骤进入下载模式，使用实际存在的下载服务。不要因为软件名称含 FDL 就自动上传任意 FDL，不使用通用擦除、重分区或 NV 写入命令。

先备份目标分区、启动链相关分区、分区表和需要的恢复材料。关键静态分区至少做独立重复读取，要求大小及摘要一致。易变 NV 必须单独记录：长会话读数不一致时，不能宣称已获得一致的全机备份；冷启动重复一致只增加证据，不能证明完整恢复可行。

写入工具应绑定设备及物理 USB 路径，固定分区白名单、预期旧摘要、新镜像摘要和大小。先完成 dry-run/离线校验及恢复方案审查，再执行实际写入。不要把 mock 测试当作真实 USB 传输测试。

## 4. 分阶段刷写

已完成的实机路线：先 TrustOS B，再修改后的 init_boot B。它依赖该设备当时的 B 槽位状态，不能机械地迁移到 A 槽位或不同固件。

每一步都必须：

1. 重新读取并核对当前关键分区，确认设备状态未漂移。
2. 固定待写入的候选字节；仅写计划中的单一分区。
3. 检查传输 ACK，完整读回，与候选逐字节或强摘要比较。
4. 检查其他受保护的关键分区未变化。
5. 所有检查通过后才重启，确认首页和 Wi-Fi 工作。

部分写入、读回不符、USB 中断均应立即停止；此时原来的恢复前置摘要可能已失效，不能盲目重复执行或自动重启。

## 5. 分开诊断 Root 与 ADB

Magisk 在设备内部运行、设备内部 `su` 返回 root、Mac 获得稳定交互式 root，是三个不同层级。

本案例先通过短时启动观察器，经用户启用的文件共享取回白名单日志，确认 Magisk 已运行，但 USB ADB 几秒后被撤销。观察器需有有限运行时间、路径约束和随机本地标记；不要收集密码、完整属性表、完整设置库或个人文件。

设置 Android 全局 `adb_enabled=1` 后首次仍回退；随后用户在原厂 Web UI 将 USB 协议从 Auto 改为 RNDIS 并重启，才得到稳定 ADB。**这是一次有多项前置变化的成功序列，不是证明 RNDIS 单独修复问题的对照实验。** 最终实际接口仍是 NCM + MTP + ADB。

## 6. 验收与保留证据

- 使用本机已授权 ADB，在正确设备上运行只读身份和版本检查；本案例使用 `/debug_ramdisk/su -c id` 与 `/debug_ramdisk/magisk -v`。
- 连续多次检查，覆盖启动完成后的数分钟；记录 USB 接口、adbd 和实际 root 返回值。
- 核对 USB 授权校验开启、TCP ADB 关闭；不要把开启远程无认证 ADB 当成修复。
- 启动 helper 为 Android shell UID 2000 写入 Magisk 授权策略，并保留已有 ADB 公钥。这意味着所有已有授权主机都可能通过 shell 取得 Root；应由设备所有者审查已有授权，不应把它理解成仅授权当前 Mac。
- 确认重启后的首页、Wi-Fi 连接和互联网访问。
- 移除不再需要的共享诊断副本、临时监听进程；保留离线备份及经核对的恢复说明。

单次重启后数分钟稳定，不代表长期、所有重启或其他主机均已验证。恢复 stock init_boot 也不会自动恢复 TrustOS 或已经写入的 Android 全局设置。
